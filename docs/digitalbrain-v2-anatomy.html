Anatomy and Physiology

The graph is anatomy: neurons and the synapses between them, durable, weighted, slowly changing. A firing is physiology: a signal crossing that graph, transient, traced, gone. v1 spent one word — Synapse — on both. Separating them is the whole of v2.

Proposed · Q1

Three words, three things

In v1, Synapse is an abstract record — a message. But everything you want a synapse to do (decay, expire, carry weight, be discovered by similarity) is behaviour of a connection. One word cannot be both. CoreV2.cs shows the collision literally: it declares record Synapse and class Synapse : Grain<SynapseState> eleven lines apart.

Neuron

The actor. A journaled Orleans grain. Owns durable state, a set of synapses, and a handler table. Every neuron is its own consistency boundary — the single writer of its own state.

Synapse

The connection. A directed, typed, weighted edge from one neuron to another. It potentiates when it carries a useful signal, decays when it doesn't, and is pruned when it falls below threshold. It is the unit of learning.

Signal

What travels. An immutable record crossing a synapse. Carries correlation and causation. Journaled at both ends. Formerly named Synapse; the rename is the one breaking change v2 asks for.

The sentence that decides it: “a neuron fires a signal along a synapse.” Every later idea — Hebbian weights, similarity search over connections, pruning dead paths — parses cleanly under this vocabulary and does not parse at all under v1's.

Four kinds of citizen

You asked whether a UI button is an entity and where a pasted image's bytes live. docs/JOURNALS.md already ratifies the answer and v2 keeps it: neurons own traffic journals, entities own snapshots, memory owns history. v2 adds the synapse as a first-class citizen and the activity as its trace.

Where the image bytes go

Not in the grain. An ImageEntity holds a reference — blob URI, content hash, MIME type, dimensions, caption, and the embedding vector — while the bytes sit in blob storage. Grain state is replicated and compacted; megabyte payloads there are a durability and memory bug, not a design. The entity is what the vector index points at, which is why the metadata lives with the reference rather than with the bytes.

A UI button is the same shape: small persistent state, no synapses, no journal, read directly by Flutter, mutated only when a neuron handles the signal its press produced.

One message, many neurons

Your example: a user message arrives and a compliance check, the assistant, memory and the activity tracker all wake up — and the assistant then spawns more. That is fan-out, and the interesting question is who decides the receiver set. Hard-coded subscriptions give you a message bus. Letting the synapse set decide gives you a brain.

Open · needs your call

How a signal finds its receivers

Three sources feed the receiver set, in order. This is the mechanism that makes “as many capabilities as possible” safe rather than chaotic: capability is declared in types, remembered in synapses, and only searched for when the first two come up empty.

The risk to name out loud: tier 3 makes routing non-deterministic, which makes the system hard to test and hard to debug. The mitigation is that tier 3 never fires instead of tiers 1–2 and never fires a blocking receiver — it can only add observers. A “strict mode” flag that disables tier 3 entirely keeps every test deterministic.
Proposed

Decay without a million timers

You want synapses to expire and decay. The naive reading — a timer per synapse — costs one Orleans reminder per edge and will not survive the first thousand neurons. It is also unnecessary: decay is a pure function of elapsed time, so it can be computed on read. 

// Stored: weight at a known instant. Never a background job.
public readonly record struct Synapse(
    NeuronId Source,
    NeuronId Target,
    string SignalType,
    double Weight,
    DateTimeOffset LastFiredAt,
    SynapseKind Kind)          // Innate | Learned | Discovered
{
    // Read-time decay: no timer, no reminder, no sweep on the hot path.
    public double WeightAt(DateTimeOffset now, double halfLife) =>
        Weight * Math.Pow(0.5, (now - LastFiredAt) / halfLife);

    public bool IsPruned(DateTimeOffset now, double halfLife, double floor) =>
        Kind != SynapseKind.Innate && WeightAt(now, halfLife) < floor;
}
  • Potentiation — a firing that the receiver handled raises Weight and stamps LastFiredAt. An unhandled signal does not.
  • Decay — computed at read. A synapse nobody uses is already weak the next time anyone looks.
  • Pruning — one reminder per neuron (not per synapse) sweeps its own set on a slow cadence, purely to reclaim storage.
  • Innate synapses never decay — they come from IHandle<T> declarations and are as durable as the code.
Open · correction inside

Neurons that touch the outside world

“Start monitoring this repository” has to end with an external event arriving inside the graph. Biology already names the split: afferent neurons carry the world inward, efferent neurons carry action outward, and everything between them is an interneuron. A webhook receiver is afferent; an HTTP client or a shell call is efferent.

But a grain cannot own an ASP.NET pipeline. Grains migrate between silos, deactivate when idle, and exist in multiple replicas over their lifetime; an HTTP listener does none of those things. What the neuron owns is the route declaration as durable state. The silo owns the listener and reads those declarations.

Settled · R3·1

A script is a neuron. That's the whole design.

Your PR-verification flow — clean, build, test, then three review agents in parallel — needs deterministic order, which is the opposite of the emergent fan-out on the previous pages. Biology has both: a reflex arc fires along whatever is wired, while a motor plan executes a sequence the cortex composed. v2 does not need a second runtime for the second one. Sequencing is await. Parallelism is Task.WhenAll. The trigger is IHandle<T>. A script is just a neuron whose handler happens to have been written by the system. 

// Generated at 09:14 from "verify every new PR like this".
// Nothing here is a new concept — it is an ordinary neuron.
public sealed class PrVerificationNeuron : Neuron, IHandle<PullRequestOpened>
{
    public static string Description =>
        "Verifies a pull request: clean, build, test, then three parallel reviews.";

    public async Task HandleAsync(PullRequestOpened pr, CancellationToken ct)
    {
        await FireAsync<IGitNeuron>(new Clean(pr.Repo), ct);          // sequential
        await FireAsync<IDotNetNeuron>(new Build(pr.Repo), ct);
        await FireAsync<IDotNetNeuron>(new Test(pr.Repo), ct);

        var reviews = await Task.WhenAll(                              // parallel
            FireAsync<IReviewAgent>("quality",      new Review(pr.Diff), ct),
            FireAsync<IReviewAgent>("architecture", new Review(pr.Diff), ct),
            FireAsync<IReviewAgent>("tests",        new Review(pr.Diff), ct));

        await EmitAsync(new PrVerdict(pr.Number, reviews));
    }
}

Genotype / phenotype

The source is the durable artifact — persisted, hashed, signed. The assembly is re-created on every silo start by compiling it into a collectible load context. A script survives restarts the way DNA survives cell death: the code is the record, the running type is an expression of it.

The compiler is the verifier

Generated code is compiled against module contracts before anything runs. Errors return to the author neuron as an ordinary signal and the repair loop is ordinary graph traffic. This is the concrete payoff of "typed C# only": the system can check its own work without executing it.

Capability-free by construction

A script has no ambient authority. It cannot open a file, spawn a process, or reach the network — it can only FireAsync at effector neurons. What it can do is exactly which effectors its owner has granted. Growth adds nodes, never attack surface.

Effectors are the only side effects

IGitNeuron, IDotNetNeuron, IShellNeuron, IRoslynNeuron — the typed integration layer your survey named IAW the winner for. Every side effect in the system passes through one of these, so every side effect is journaled, correlated, and revocable.

Decided: one authoring surface. Smart Prompts are retired. The ARCHITECTURE.md position — "English + binding chips, not generated C#", executing as StartExecution(SmartPromptWorkload) — is superseded. English is still how you ask; a compiled neuron is what you get. There is no second runtime, no workload descriptor, and no interpreter.

Proposed · R2·5 revised

Three learning loops, at three speeds

You separated two things I had collapsed: embeddings are for memory and search, while ML is for getting better at you — learning from corrections. Those are different loops with different latencies, and only one of them is ML at all.

LoopSpeedSignal it learns fromWhat changesTechnology
Hebbian every fire the receiver handled it synapse weight arithmetic — no model
Corrective every correction UserCorrected(did, wanted) weight down on the bad path, up on the chosen one; a durable preference with an embedding embeddings (MEAI)
Predictive nightly, offline journals + corrections as labelled pairs the order of the receiver set ML.NET ranker

The whole ML.NET commitment is one interface, designed now and left unimplemented: 

// The only seam ML ever touches. Default sorts by Hebbian weight.
// A trained ranker replaces it later — and can only REORDER.
public interface ISynapseRanker
{
    IReadOnlyList<Synapse> Rank(
        IReadOnlyList<Synapse> candidates,
        RoutingContext context);
}
Why "reorder only" is the load-bearing constraint. A ranker that could add or remove receivers would make every test non-deterministic and every incident unexplainable. One that only reorders is safe to ship half-trained, safe to turn off, and safe to compare against the arithmetic baseline — because both produce the same set. Corrections are recorded from day one so the training data accumulates long before a model exists; that is the part that cannot be retrofitted.

Four traffic planes, deliberately separate

PlaneShapeStorageRetentionContract?Used for
Signal directed, along a synapse traffic journal, both ends512 entries public the graph — everything observable

Why internal events are not just self-signals. Weight bookkeeping fires far more often than real traffic. Routed through the 512-entry traffic journal it would evict the neuron's actual history within minutes of load — the observable record destroyed by its own accounting. Hard rule: a neuron may never declare IHandle<T> for its own internal event.

Open · Q6 — scope contract

The proof: what the console prints on day one

ModernCQRS proves its architecture with handlers that only Console.WriteLine. The same discipline here: no AI, no persistence backend beyond in-memory, no modules. If this program runs and prints this output, v2's central claim — that the edge is a real, durable, weighted, learnable thing — is true. If it can't, no amount of further design saves it. 

// Program.cs — the whole day-one surface
await using IDigitalBrain brain = await DigitalBrain.CreateAsync(args);

var chat  = brain.Get<IChatNeuron>("main");
var greet = brain.Get<IGreeterNeuron>("default");

// 1. Fire twice. The second fire potentiates the same synapse.
await chat.FireAsync(new UserMessageReceived("hello"));
await chat.FireAsync(new UserMessageReceived("hello again"));

// 2. Print the anatomy — the durable graph.
foreach (var s in await brain.GetSynapsesAsync())
    Console.WriteLine(s);

// 3. Print the physiology — what actually travelled.
foreach (var d in (await chat.ReadJournalAsync(JournalKind.Outgoing)).Delta)
    Console.WriteLine(d);

Four claims, each falsifiable by that output:

  1. Neurons dispatch by type. The greeter's handler ran without the chat neuron naming it.
  2. Synapses are real and durable. They print with a source, a target, a signal type and a weight.
  3. Synapses learn. w=0.72 after two fires rather than a constant — potentiation happened, and it survives a restart.
  4. Anatomy and physiology are separate. Two lists, two shapes, two retention policies.
