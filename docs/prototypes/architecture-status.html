Implementation lies

These are not architecture debates. They must not stay green.

1 Fabricated acceptance. DefinitionAuthoringService.RunScenariosAsync returns Passed=true and {"passed":true,"results":[]} without executing expectations. Activation then treats missing expectations as allowed.

2 Activation is not one commit. Each definition is marked active, then the registry is committed, then subscriptions are applied. Interruption can expose a partial set. Removed subscriptions are not removed.

3 Control APIs that do not control. RetryExecutionAsync only reads. RunAgainAsync returns a new id without admitting work.

4 Process bootstrap loses capability. Context.ConnectAsync stores the worker capability in AsyncLocal inside an awaited method; the caller does not retain it. Replay also mints a fresh caller and SignalId.

5 Supervisor is serial and forgetful. It waits for one script process before claiming another. ClaimPending removes work before a durable ack.

Full review: docs/superpowers/reviews/2026-09-07-context-implementation-review.md. I will not re-approve settled semantics to make these easier.
